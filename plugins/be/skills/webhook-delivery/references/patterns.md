## Signing

```ts
import { createHmac } from "node:crypto";

// secrets: the current one first, plus the old one during a rotation's overlap
export function buildWebhookHeaders(eventId: string, body: string, secrets: readonly Buffer[]) {
  const timestamp = Math.floor(Date.now() / 1000).toString();
  const signedContent = `${eventId}.${timestamp}.${body}`; // body: the exact string sent
  const signatures = secrets.map(
    (secret) => `v1,${createHmac("sha256", secret).update(signedContent).digest("base64")}`,
  );
  return {
    "content-type": "application/json",
    "webhook-id": eventId,
    "webhook-timestamp": timestamp,
    "webhook-signature": signatures.join(" "),
  };
}
```

A secret is shown as `whsec_` plus its base64; the HMAC key is the decoded bytes, not the string. Check the implementation against the spec's published test vectors before the first release. Event ids and timestamps are generated by the server and never contain a `.`.

## Checking a customer's address

```ts
import { lookup } from "node:dns/promises";
import ipaddr from "ipaddr.js";

// Anything but a public unicast address is refused: private, loopback, link-local
// (169.254.169.254 is the metadata server), carrier-grade NAT, unique-local, reserved.
function isPublicAddress(address: string): boolean {
  const parsed = ipaddr.process(address); // turns ::ffff:10.0.0.1 into 10.0.0.1
  return parsed.range() === "unicast";
}

export async function resolveWebhookTarget(rawUrl: string): Promise<{ url: URL; address: string }> {
  const url = new URL(rawUrl);
  if (url.protocol !== "https:") throw new ValidationError("Webhook URLs must use HTTPS");
  if (ipaddr.isValid(url.hostname.replace(/^\[|\]$/g, ""))) throw new ValidationError("Use a hostname, not an IP address");
  if (url.port && url.port !== "443") throw new ValidationError("Use the standard HTTPS port");

  const addresses = await lookup(url.hostname, { all: true }); // A and AAAA
  if (addresses.length === 0 || !addresses.every(({ address }) => isPublicAddress(address))) {
    throw new ValidationError("That address can't receive webhooks");
  }
  return { url, address: addresses[0].address }; // connect to this address, not a fresh lookup
}
```

Send with an HTTP client whose connection uses the checked address (an undici `Agent` whose `connect.lookup` returns the checked address, or an egress proxy that does the same check), with redirects off, and the URL's hostname kept for TLS and the `Host` header. Run the check at registration and again before every attempt.

## The retry schedule

The schedule the Standard Webhooks spec gives as an example, spanning about three days:

| Attempt | Delay after the last | Since the first |
| ------- | -------------------- | --------------- |
| 1       | immediately          | 0               |
| 2       | 5 seconds            | 5 s             |
| 3       | 5 minutes            | ~5 min          |
| 4       | 30 minutes           | ~35 min         |
| 5       | 2 hours              | ~2.5 h          |
| 6       | 5 hours              | ~7.5 h          |
| 7       | 10 hours             | ~17.5 h         |
| 8       | 14 hours             | ~31.5 h         |
| 9       | 20 hours             | ~51.5 h         |
| 10      | 24 hours             | ~75.5 h         |

Add up to 10% random jitter to each delay. A `Retry-After` longer than the next delay replaces it. Each attempt is its own queue task, scheduled for its time; the delivery record keeps the attempt count and the next attempt's time, so the log can show it.
